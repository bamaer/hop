= Graph Database Connection

== Description

A graph database connection connects to a graph database over the Bolt protocol.
The graph database type determines the defaults and the server specifics:

[options="header"]
|===
|Type |Defaults

|Neo4j
|Automatic configuration with the `neo4j://` scheme on port 7687, the defaults of a xref:metadata-types/neo4j/neo4j-connection.adoc[Neo4j Connection].

|Memgraph
|A direct `bolt://` connection on port 7687 without encryption.
Memgraph only offers routing in its high availability setup.

|Amazon Neptune
|A `bolt://` connection on port 8182 with encryption, which Neptune requires.
|===

All the transforms and actions of the Neo4j plugin, the Neo4j execution information location and Neo4j logging accept a graph database connection wherever they take a Neo4j connection.
Their connection lists show both kinds.
When a Neo4j connection and a graph database connection have the same name, the Neo4j connection is used, so existing projects keep working exactly as before.

Graph database connections are serialized as JSON in the Hop metadata folder under

`metadata/graph-database-connection/`

== Options

The options of all three types are the same as the options of a xref:metadata-types/neo4j/neo4j-connection.adoc[Neo4j Connection].
They are grouped in four tabs:

[options="header"]
|===
|Tab |Options

|Connection
|Server or IP address, database name, Bolt port, browser port, username and password.

|Protocol
|Automatic configuration, protocol (URL scheme), routing, routing policy, encryption and trusting all certificates.
Every on/off option has a variable alternative which, when set, overrides it, for example `'${NEO4J_ENCRYPTION}'`.

|Advanced
|Connection liveness check timeout, maximum connection lifetime, maximum connection pool size, connection acquisition timeout, connection timeout and maximum transaction retry time, all in milliseconds.

|Manual URLs
|URLs which replace the ones built from the other options, for example `bolt://localhost:7687`.
|===

Use the *Test* button to verify the connection.

== Converting a Neo4j connection

Existing Neo4j connections keep working as they are: there is no need to convert them.
To convert one, open it in the metadata perspective and click *Convert...*.
*Convert all...* converts all the Neo4j connections of the project at once. A Neo4j connection is skipped when a graph database connection with the same name exists already.
This saves a graph database connection of type Neo4j with the same name and settings and removes the Neo4j connection.
Pipelines, workflows, the Neo4j execution information location and Neo4j logging find connections by name, so they keep working without changes.
Older versions of Hop don't know graph database connections, so only convert when every Hop installation that uses the project can read them.

== Compatibility

The transforms and actions of the Neo4j plugin generate Cypher.
The database type determines which index and constraint statements are generated, and the Neo4j Index and Neo4j Constraint dialogs only offer what the database supports:

[options="header"]
|===
|Feature |Neo4j |Memgraph |Amazon Neptune

|Node indexes
|Yes, named
|Yes, unnamed: identified by label and properties
|No, Neptune manages its indexes

|Relationship indexes
|Yes
|Yes, on a single property
|No

|Unique and existence constraints on nodes
|Yes
|Yes. Existence constraints are on a single property.
|No

|Node key constraints and relationship constraints
|Yes
|No
|No

|Index and constraint changes in a transaction
|Yes
|No: the Neo4j Cypher Script action runs every statement in its own transaction on Memgraph
|Not applicable
|===

Notifications of the database, like deprecation warnings or the query planner hints of Memgraph, are advice about a statement which succeeded.
The Neo4j Output, Neo4j Graph Output and Neo4j Cypher transforms log them, warnings at the basic log level and informational notifications at the detailed log level, and never fail on them.

Cypher you write yourself, for example in the Neo4j Cypher transform, has to use the syntax of the database.
The Neo4j perspective is only supported on Neo4j.
Neo4j logging and the Neo4j execution information location are supported on Neo4j and also write to Memgraph.
